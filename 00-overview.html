· The Lego-Style Build — Why the Order Matters

The four folders are not four independent topics you could take in any order. Each one is a layer that only makes sense once the layer under it is in place — the same way a Lego model is built bottom-up, not by snapping on whichever brick looks interesting. Skip a layer and the next one has nothing to click into: Folder 3's evaluation material assumes an agent and tools already exist to evaluate (Folders 1-2); Folder 4's deployment and monitoring material assumes you already know what "good" looks like for that agent (Folder 3).

这四个文件夹不是四个可以随便挑顺序来学的独立主题。每一层都只有在它下面那一层已经搭好之后才讲得通——就跟搭乐高一样，是从底往上搭的，不是看哪块积木好看就先拿哪块。跳过一层，下一层就没有东西可以卡上去：Folder 3 的评测内容,是建立在"已经有一个 agent 和一些工具可以拿来评测"这个前提上的（也就是 Folder 1-2 搭出来的东西）；Folder 4 的部署和监控内容,是建立在"你已经知道这个 agent 的'好'应该是什么样子"这个前提上的（也就是 Folder 3 教的东西）。

What each layer adds, and why it needs the layer below it
LayerWhat it addsWhy it needs the layer below
1. RetrievalAn agent that can find and ground answers in real documents/data (AI Search, Lakebase, Genie)Foundation — nothing above this exists without something to retrieve from
2. Tools & OrchestrationAn agent that can act (UC functions, MCP tools) and coordinate (single/multi-agent, 3 frameworks)Needs Layer 1's retrieval patterns as the first tools worth building
3. EvaluationA vocabulary and toolset for judging whether the agent from Layers 1-2 is actually goodNothing to evaluate without an agent and tools that already exist and run
4. Deploy & MonitorShipping that agent live, and running Layer 3's evaluation continuously on real trafficCan't define "monitor for quality" without Layer 3's scorers and judges already defined
